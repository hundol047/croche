# 기록·입력 보존과 복습 · 2026-10-08

## 손상 원본을 덮어쓰지 않는 저장

키가 없는 경우만 빈 기록으로 시작합니다. JSON 파싱 실패, 잘못된 루트/필수 배열과 기본 사건 구조를 만나면 읽기·다음 쓰기를 중단합니다. 기존 profile·legacy DNA/오답/Trap·learning·session에 적용합니다. 모든 가능한 데이터 훼손을 발견하는 전체 스키마 검증은 아닙니다.

정상 값을 갱신하기 전에 `${key}:backup`에 직전 정상 원문을 보존합니다. 백업 저장이 실패하면 기본 값은 갱신하지 않습니다. 학습 사건과 DNA는 기존처럼 learning 하나에 저장하고 같은 사용자/런타임 큐에서 직렬화합니다. 유효한 값 저장이나 재시도의 직전 상태이므로 백업이 최신 값과 같을 수도 있으며, 항상 최신 변경을 포함한다고 보장하지 않습니다.

앱 시작 시 손상을 발견하면 ‘기록 복구’ 화면을 엽니다.

1. **손상 원본 내보내기**: 해당 키의 원문·백업·손상 보존본을 JSON 파일로 받습니다. 다른 프로필을 포함하지 않으며 서버에 전송하지 않습니다.
2. **이전 기록으로 복원**: 백업의 기본 구조를 확인하고, 손상 원문을 별도 보존한 뒤 정상 백업으로 교체합니다. 최근 변경 일부는 복원되지 않을 수 있습니다.
3. **복원할 백업이 없는 경우**: 경고를 펼쳐 내용을 확인한 후 해당 기록만 비웁니다. 먼저 손상 원본을 별도 키에 보존하고, learning을 비우는 경우 진행 중 session도 보존 후 비워 기존 제출이 자동 재전달되지 않게 합니다. 보존 쓰기가 실패하면 초기화를 진행하지 않습니다.

원문 보존은 손상 내용을 자동으로 해석·복원한다는 뜻이 아닙니다. 실행 중 발생한 읽기/쓰기 오류도 원문 덮어쓰기를 거부하지만 전체 복구 화면은 새로고침 후 앱 시작 검사에서 열립니다. 브라우저 저장소 전체를 삭제하거나 기기를 잃으면 같은 저장소의 백업·손상 원문도 사라질 수 있습니다.

## 제출 전 입력

풀이·Trap 화면은 답, 풀이, 확신도 변경을 사용자·현재 문제 세션에 직렬로 저장합니다. 답은 256자, 풀이는 4,000자이며 상태를 ‘저장 중/저장됨/저장 실패’로 표시합니다. 실패 시 화면 입력은 남고 ‘입력 저장 다시 시도’를 누를 수 있습니다. 저장됨은 서버 전송이나 제출 완료가 아닙니다. 제출 전에는 학습 사건·점수·HIT·DNA를 만들지 않습니다.

새로고침하면 같은 문항의 작성 중 입력을 복원합니다. 새 문제·새 복습 시도·새 Trap에는 이전 초안을 옮기지 않습니다. 제출 후 늦게 도착한 초안 쓰기는 제출을 지우지 않습니다. 이미 제출한 답을 사용자가 명시적으로 수정하면 새 초안을 작성하며 새 제출은 별도 시도입니다. 동일 전달 토큰의 저장 재시도는 기존 제출과 초안을 보존합니다.

## 오답·복습 기록

홈과 리포트에서 ‘오답·복습 기록’으로 갑니다. 문제별 마지막 판정을 보여주고 오답/전체 풀이, 학습 단계, 과목, 단원·원문 검색으로 찾습니다. 상세 화면에서 원문·보기·내 답·풀이·정답·해설·이전 제출을 읽고 다시 풀 수 있습니다. 다시 풀기는 출제 횟수나 소진 상태를 초기화하지 않으며 새 제출 사건으로 기록합니다.

새 사건은 문항 스냅샷을 보관합니다. 이전 사건은 공개한 기본/단원/버전별 변형 ID로 원문을 복원할 수 있을 때만 재풀이를 제공합니다. 원문을 찾을 수 없는 과거 사건은 답과 분석을 그대로 보여주고 임의의 문제를 만들어 넣지 않습니다.

‘학습 기록 내보내기’는 현재 프로필과 learning 기록만 JSON으로 받습니다. **파일 가져오기/자동 복원, 계정 인증, 서버 백업, 다중 탭 트랜잭션, 기기 간 동기화는 구현하지 않았습니다.** 파일에는 답안·이름·학습 기록이 포함될 수 있어 보관·공유 여부를 사용자가 결정합니다. Web은 다운로드, 네이티브 구현은 공유 창이지만 네이티브 실행은 미검증입니다. 로컬 프로필 구분은 인증된 사용자 계정의 접근 제어가 아닙니다.
